OtaS 構成図

AI エージェントに作業を任せる Linux ベースの OS です。エージェントはタスクごとにサンドボックスで動き、外に作用する操作はすべてブローカーを通ります。ブローカーは操作をポリシーで判定し、監査ログに記録します。このページでは、実行時の部品のつながり、クレートの依存関係、リポジトリの配置を図にしています。

実行時の構成

人間は CLI からデーモン otasd に依頼します。otasd はエージェントをサンドボックスで起動し、そのタスク専用の窓口を標準入力として渡します。エージェントがファイルを書けるのは作業領域だけで、正本に反映するかどうかは人間が決めます。

  1. 依頼する

    人間がタスクを依頼します。プログラム・引数・権限（read / write / tool / model）を渡します。

    otas submit req.json ／ otas（対話モード）

  2. 作業領域を用意する

    otasd は、権限の範囲のデータだけを見せる作業領域を作ります。見せたデータのラベル（私的など）はタスクに取り込まれます。

  3. サンドボックスで起動する

    エージェントにタスク専用の窓口を stdin として、作業領域の場所を OTAS_DATA として渡します。

  4. 操作はすべてブローカーを通る

    ツールの呼び出しもモデルへの推論も、判定されて監査ログに残ります。高リスクの操作は承認待ちになります。

    otas pending ／ approve ／ reject ／ watch

  5. 変更を確かめて反映する

    エージェントが書いたファイルは作業領域にたまります。人間が差分を見て、コミットするか捨てるかを決めます。コミットしたファイルにはタスクのラベルが付きます。

    otas diff ／ commit ／ discard

  6. 版から戻す

    正本は版として残るので、前の状態に戻せます。

    otas versions ／ rollback

ブローカーとポリシーの判定順

どのアダプタやプラグインを差し替えても、この順序は変わりません。

ブローカーの処理（呼び出し1回ごと）

  1. タスクの権限とラベルを取り出す
  2. ポリシーで判定する
  3. 実行する前に監査ログに記録する（記録できなければ実行しない）
  4. 実行し、結果のラベルをタスクに取り込む
  5. 結果を監査ログに記録する
許可拒否承認待ち

標準ポリシーの判定（最初に引っかかったところで結論）

  1. 実行環境の保証が足りなければ、外部に作用する操作を拒否する
  2. タスクに権限がなければ拒否する
  3. 情報フロー制御（otas-ifc）の判定に従う

Rule of Two：「信頼できない入力」「機密データ」「外部への作用」の3つを同時に満たす操作は、人間の承認なしには実行しません。秘密情報に触れたタスクは、承認があっても外部に作用させません。
